# Code Research

对当前项目进行深度研究，系统性地理解项目的设计哲学、架构决策、Day 0 产品和技术方案意图、演进历史、实现地图、源码阅读路径、前置基础知识模块、代码质量地图、核心机制与数据流。

## 安装

```bash
/plugin install coding@fawetian-plugins
```

## 触发方式

在对话中输入 `code-research` 触发，例如：

- `code-research`
- `帮我深入理解这个项目的架构`（结合 `code-research` 触发词使用效果最佳）

## 使用示例

**场景一：快速了解项目整体架构**

```
code-research 给我一个大致的理解
```

仅执行架构主题分析，输出项目核心模块关系图和设计概览，适合快速上手新项目。

**场景二：深入理解某个特定功能**

```
code-research 我想理解认证模块的实现
```

聚焦于指定功能，拆解其核心机制，追踪调用链，解释关键设计决策。

**场景三：准备参与贡献代码**

```
code-research 我想为这个项目贡献代码
```

执行完整研究流程，并行启动多个专项研究 Agent，覆盖架构、核心机制、数据流、依赖关系、工作流、学习路径、演进历史、实现地图、第一性原理设计推演、Day 0 复原和代码质量地图，最终汇总为完整研究报告。

**场景四：规划源码阅读路径**

```
code-research 分析这个项目的代码目录和结构，规划一条源码阅读路径
```

从阅读源码的角度分析目录结构、入口文件、核心模块和可暂时跳过的目录，产出独立的 `06_learning_path.md`。

**场景五：按背景补齐理解项目所需基础知识**

```
code-research 我是后端工程师，前端基础比较薄弱，深入理解这个项目需要补哪些基础知识模块
```

根据用户背景和项目源码/依赖，列出深入理解当前项目前需要补齐的基础知识模块、为什么需要、项目中的证据、掌握到什么程度即可，并并入 `06_learning_path.md`。

**场景六：分析系统为什么演进成现在这样**

```
code-research 分析这个项目的演进路线和原因
```

基于目标项目的 Git commit history 和关键 diff 分阶段梳理真实演进过程，再映射到当前代码结构。

**场景七：从 0 重新思考系统设计**

```
code-research 如果从第一性原理出发，怎么设计这套系统
```

不按 commit 时间线复述历史，而是从最小可行设计开始，逐步推演当前系统中的模块、状态、接口和复杂度为什么需要存在。

**场景八：站在源码作者 Day 0 视角理解产品和技术方案**

```
code-research 站在源码作者 Day 0 视角，分析这套系统的需求、MVP 边界和技术方案
```

从现有源码、README、文档和 commit 证据中，反向复原作者开工第一天会如何定义产品边界、MVP、初始技术方案和后续演进压力，产出 `10_day0_product_technical_design.md`。这不是给未来新功能写 RFC 或 implementation plan。

**场景九：分析代码质量和可维护性风险**

```
code-research 分析这个项目的代码质量，给我一份质量地图
```

直接阅读目标项目源码，基于具体文件、函数、类型、配置或调用链证据，识别模块边界、复杂度来源、修改风险、测试缺口、错误处理、代码一致性和可简化点，产出 `11_quality_map.md`。这不是逐行 code review、漏洞扫描、性能 profiling 或自动修复。

## 输出

研究结果以中文输出，保存在项目的 `docs/code-research/` 目录下：

- `RESEARCH_PLAN.md` — 研究计划与汇总，包含各主题文档索引
- `01_architecture.md` — 架构概览（含 Mermaid 图表）
- `02_mechanism_[名称].md` — 核心机制说明
- `03_data_flow.md` — 数据流与状态管理
- `04_dependencies.md` — 依赖关系与生态
- `05_workflow.md` — 核心工作流（端到端业务流程 + 模块内部执行流程）
- `06_learning_path.md` — 源码阅读路径，包含前置基础知识模块、目录结构分析、入口文件、核心模块、推荐阅读顺序和可先跳过的目录
- `07_evolution_history.md` — 基于 commit history 的系统演进路线和原因
- `08_implementation_map.md` — 历史能力到当前代码落点的实现地图
- `09_design_evolution.md` — 从第一性原理出发的设计演进推演
- `10_day0_product_technical_design.md` — Day 0 产品需求、MVP 边界、初始技术方案和作者视角设计取舍复原
- `11_quality_map.md` — 基于源码证据的代码质量和可维护性风险地图

## 重复调用

如果 `docs/code-research/` 已存在，skill 会自动检测并让用户选择：

- **完整覆盖**：删除旧文件，重新研究（适合代码大幅变化后）
- **继续未完成**：只补充缺失的专题文件（适合上次中断的研究）
- **归档后重来**：旧文件重命名为 `_archived_日期/` 后缀，重新开始
- **研究新专题**：在子目录 `docs/code-research/{topic}/` 下做专项研究，不影响已有研究
