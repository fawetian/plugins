# 默认 Goal 策略

生成可以直接复制执行的目标指令。

这个 skill 不应该假装理解所有领域。可靠性来自：保守默认值、权威上下文发现、具体可验证证据、有界迭代，以及高风险暂停规则。

## 输出优先级

中文用户默认按这个顺序输出：

1. `推荐执行版（中文，可直接复制）`
2. `默认选择理由`
3. `可选调整`
4. `你可以直接回复`
5. `Goal Draft (English-compatible)`

不要把半填空模板放在推荐执行版前面。用户经常直接复制第一段。

## 默认优先规则

如果用户给的是模糊任务，但不确定性属于低风险，直接选择最稳妥的默认值并继续。

好的默认值：

- 新 app / 网站 / 工具：先做本地 MVP
- 现有仓库：先检查项目脚本、文档和约定
- 没有部署要求：只做本地运行验证
- 没有鉴权要求：不加入登录、后端、云同步、付费 API 或账号系统
- 没有设计系统要求：遵循现有风格；如果是新项目，选择克制、可用的界面
- 不知道测试命令：先发现 `package.json` scripts、Makefile、CI 配置、Xcode scheme 或项目文档，不要凭空编造命令
- 没有高级功能要求：实现最小但完整的用户可见工作流

始终补一句简短理由：

```text
默认选择理由：先做本地 MVP，因为它能最快验证核心体验，同时避免账号、后端和发布流程拖慢第一版。
```

## 懒人选项

只有当某个选择会显著改变成本、风险或方向时，才用编号选项提问。

```text
可选调整
1. 项目形态：A 新建本地 MVP（默认） / B 改现有项目 / C 先做原型
2. 范围：A 核心流程（默认） / B 加常见增强 / C 做完整产品
3. 验证：A 本地运行检查（默认） / B 真机或线上检查 / C 发布前检查

你可以直接回复：按默认，或回复类似 1B 2A 3C。
```

选项要短。不要让用户填写冗长的开放式问卷。

## 未知领域策略

当任务涉及陌生或专业领域时，不要编造领域规则。生成 discovery-first goal。

使用这个模式：

```text
/goal 安全创建 [任务] 的第一版，先检查权威上下文，再实现最小可验证工作流。
验证：识别并检查工作区内可用的项目文档、现有脚本、样例数据、领域说明或官方参考；运行最小相关检查；完整走通一个代表性工作流，并用日志、截图、导出产物或命令输出作为证据。
约束：不编造领域规则、合规声明、数据语义或面向用户的承诺；所有结论必须由已检查上下文支持。
边界：只修改第一版工作流直接需要的文件；保持无关模块、生产数据、凭证和公开契约不变。
迭代策略：先完成发现阶段并声明工作假设，再实现一个聚焦切片；失败后使用新证据调整，而不是无依据反复重试。
完成条件：第一版工作流能在已记录假设下运行，且有证据证明结果；未解决的领域问题被清楚列出。
暂停条件：需要领域权威判断、法律/医疗/金融判断、合规审批、生产数据、付费服务或破坏性操作时暂停。
```

这样可以让目标仍然有用，同时避免 meta skill 假装懂所有领域。

## 风险分类

低风险：本地原型、本地 UI、本地文档、toy data、隔离脚本、非破坏性格式化、生成示例。

中风险：现有仓库改动、公开 UI 文案、开发环境迁移、共享配置、带测试凭证的外部 API、浏览器扩展、移动端构建。

高风险：生产数据、支付、凭证、破坏性删除、法律/医疗/金融建议、合规、隐私敏感用户数据、版权素材、App Store 或应用商店提交、线上部署、账号所有权、官方授权声明。

处理方式：

- 低风险：选择默认值并生成可直接复制的 goal。
- 中风险：选择默认值，同时加入明确边界和暂停条件。
- 高风险：用编号问题确认关键决定，或生成 discovery-only goal，并在风险动作前暂停。

## 模糊词

不要禁止模糊方向词。把它们翻译成迭代和验证。

示例：

```text
设计方向：克制、专业、有留白，避免模板感和营销页风格。
验证：用桌面和移动端截图检查首屏身份、信息层级、文字可读性、核心入口和布局重叠。
迭代策略：基于截图做最多 3 轮聚焦视觉改进，优先调整层级、间距、字体、素材处理和控件密度。
```

模糊词用于指导品味；验证证据用于证明结果是否可接受。

## 默认迭代策略

使用有界自治：

```text
迭代策略：先实现可运行第一版，再基于构建结果、运行日志和截图做最多 3 轮聚焦改进；同一错误连续失败 2 次后必须换证据来源。
```

不要写 `keep trying` 或 `until it looks good`。

## 定稿规则

用户回答选项后，输出 `最终可复制 /goal`，并尽量只给一个代码块。除非用户要求解释，否则不要重复完整说明。
